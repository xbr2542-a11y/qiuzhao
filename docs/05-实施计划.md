## S3 + S4 交付明细

### S3 数据层迁移（app/db.py）

- 新增 13 张表：settings、authorizations、search_configs、sources、tasks、task_logs、
  job_analyses、resume_facts、tailored_resumes、applications、greetings、hr_messages、notifications
- 为既有表补列：profile +10 列、jobs +11 列、resumes +2 列、events +3 列
- 迁移方式：幂等 DDL + `PRAGMA table_info` 列检查 + `ALTER TABLE ADD COLUMN`，**不删表、不改旧列名**
- 新增授权 API：`db.grant / db.revoke / db.is_authorized`
- 默认设置：六维评分权重、限流 6 次/分钟、AI provider=rules

### S4 任务系统（app/tasks.py、app/handlers.py）

- 状态机：queued → running → done / failed / stopped / paused / interrupted
- 协作式暂停：处理器在检查点让出控制权，最多延迟 0.5 秒生效；恢复时从断点继续（`resume_from`）
- 协作式停止：终态，可重新入队重跑
- 限流：任务级 `rate_limit_per_min`，采集器强制遵守（默认 6 次/分钟）
- 日志：结构化写入 `task_logs`，前端可实时查看
- 周期任务：`repeat_seconds > 0` 时自动排下一次（用于状态跟踪）
- 崩溃恢复：进程重启后残留 running / paused 任务标记为 interrupted
- 优雅关机：Ctrl+C 时正在运行的处理器在下一个检查点中断，任务标记 interrupted
- 前端「任务日志」页：新建任务、进度条、暂停/恢复/停止/重跑、实时日志

## 当前限制（诚实清单）

1. 采集器尚未实现，岗位进库目前只有"粘贴导入"一条路。
2. AI 分析未接入，只有规则评分；无 API key 时"技能差距 / 风险提示"会退化为关键词提示。
3. 浏览器自检未在真实环境跑过（沙箱内 spawn EPERM），需双击 `自检_浏览器.bat` 确认。
4. 后端无账号体系（单人本机工具的有意选择）。
5. 项目尚未纳入 git，无法回滚，建议尽早 `git init`。
6. 任务调度是**单线程串行**：同时只能跑一个任务。这对限流和风控是优点，但当采集器变多、AI 分析要并发时会成为瓶颈，届时应改为工作线程池 + 来源级串行。
7. 前端任务进度靠 2 秒轮询，不是推送；任务很多时会有轻微延迟。
8. `.tmp\pytest_j58zxi0y`、`.tmp\smoke_emrs2a15` 两个空目录是早期实验残留、带拒绝访问 ACL，需管理员权限删除。
